📖 Goal of this Document
To understand how WaveLock recognizes gestures, you must understand Dynamic Time Warping (DTW). This document is divided into two phases: First, we learn the general algorithm. Second, we see exactly how it is used in the WaveLock Python code.

P1 Phase 1: The Core Concept of DTW

1. The Problem: The "Speed" Dilemma

Imagine you want to compare two audio recordings of someone saying the word "Hello."

  • Recording A: Says it normally: "Hel-lo" (lasts 1 second).
  • Recording B: Says it slowly: "Heeeelllll-looooo" (lasts 3 seconds).

If you compare these sound waves line-by-line (at exactly the same timestamps), they will look completely different. At the 1-second mark, Recording A is finished, while Recording B is still saying "eeee." A standard linear comparison (like Euclidean distance) will tell you these are completely different words.

We need an algorithm that can stretch and squash time, matching the "H" in Recording A to the "H" in Recording B, and the "o" to the "o", regardless of exactly when they happen. This is Dynamic Time Warping.

2. How DTW Works (The Rules)

DTW finds the optimal alignment (the best matching path) between two sequences by building a matrix and finding the "cheapest" path through it. To prevent crazy impossible alignments (like matching the end of a word to the beginning of a word), DTW enforces strict rules:

  1. Boundary Conditions: The path must start at the beginning of both sequences (0, 0) and end at the end of both sequences (N, M).
  2. Monotonicity: Time only goes forward. You can't match frame 5 of Sequence A to frame 3 of Sequence B, and then move backwards.
  3. Continuity: The path can only step to adjacent cells (diagonally, right, or down). No skipping frames.

3. A Concrete Mathematical Example

Let's align two simple 1D number sequences:

  • Sequence A: [1, 3, 4, 9, 8]
  • Sequence B: [1, 1, 3, 4, 9, 9, 8]
    (Notice Sequence B is basically the same, just "slower" because it repeats 1 and 9).

Step 1: The Cost Matrix. We create a grid. Every cell contains the absolute difference (distance) between the two numbers.
Step 2: The Path. DTW uses Dynamic Programming to find the path from bottom-left to top-right with the lowest total sum.

A \ B 1134998
8 7754110
9 8865001
4 3310554
3 2201665
1 0023887

Notice the highlighted path: The 1 in Sequence A maps to both 1s in Sequence B (moving horizontally). The 9 in Sequence A maps to both 9s in Sequence B. The Total Cost = 0. DTW recognizes these sequences represent the exact same core pattern, despite different speeds!

4. The Dynamic Programming Formula

For every cell (i, j), the algorithm calculates the cheapest way to get there using this formula:

DTW(i, j) = cost(i, j) + MIN (
    DTW(i-1, j),    // Insertion
    DTW(i, j-1),    // Deletion
    DTW(i-1, j-1)   // Match (Diagonal)
)

P2 Phase 2: DTW in the WaveLock Project

Now, let's look at exactly how WaveLock uses this algorithm to recognize hand gestures in gesture_compare.py.

1. The Challenge of 3D Hand Tracking

In WaveLock, we aren't matching 1D numbers. Every single frame of video gives us 21 landmarks, and each landmark has 3 coordinates (X, Y, Z).

When you perform a gesture, you might raise your hand slowly but lower it quickly. This non-linear speed variation is exactly why we need DTW.

2. Preparing the Data (Flattening)

After Temporal Normalization, every gesture is a matrix of shape (60, 21, 3). That means 60 frames, 21 landmarks, 3 coordinates.

DTW expects a sequence of "points" in space. So, we flatten the hand data:

# From gesture_compare.py
flat_a = gesture_a.reshape(60, -1).astype(np.float64) 
flat_b = gesture_b.reshape(60, -1).astype(np.float64)

Because 21 * 3 = 63, we reshape (60, 21, 3) into (60, 63). Now, we have a sequence of 60 frames. In each frame, the "point" is a 63-dimensional vector that represents the exact shape and position of the entire hand at that millisecond.

3. The Library: dtaidistance

We use an optimized library called dtaidistance to do the heavy lifting, specifically the dtw_ndim (N-Dimensional DTW) module.

distance = dtw_ndim.distance(flat_a, flat_b)

What is happening inside this function?
It builds a 60x60 grid. But instead of the cost being simple subtraction, the cost between cell i and cell j is the Euclidean Distance in 63-dimensional space. It calculates how physically different the hand shape in Frame i (Live) is from the hand shape in Frame j (Template). Then, it finds the cheapest warping path from Frame 0 to Frame 59.

4. Wait, if both are 60 frames, why do we need DTW?

A Crucial Distinction
This is a very common point of confusion. Why use DTW if Temporal Normalization already makes both gestures exactly 60 frames long?
  • Temporal Normalization stretches or squashes the overall video so both are 60 frames long. It solves linear speed differences (e.g., a 3-second wave vs a 2-second wave).
  • DTW solves non-linear speed differences.
    • Imagine Template Gesture: Raise hand (30 frames), Lower hand (30 frames).
    • Imagine Live Gesture: Raise hand slowly (45 frames), Lower hand fast (15 frames).
    • Both are 60 frames total! But frame 30 of the Live gesture is still moving up, while frame 30 of the Template gesture is at the peak.

If you compared them directly (frame 30 vs frame 30), it would fail completely. DTW "warps" the comparison, correctly mapping the slow 45-frame raise to the standard 30-frame raise.

5. The Output and Thresholding

The distance returned by DTW is a single float number representing the total cost of the warping path.

DistanceMeaning
0.0Exact mathematically identical match
~0.5 to 1.5Normal human variation of the same gesture
~2.5 to 5.0+A completely different physical gesture

In gesture_compare.py, this number acts as Security Gate 1. We compare it against the user's specific threshold saved in config.json (e.g., 2.3094).

passes_distance = (distance <= threshold)

If the distance is lower than the limit, the overall physical motion of the gesture is approved, and the system moves on to check the specific fingers (Gate 2, 3, and 4).
