! Overview: The Registration Lifecycle

Authentication is only as good as the initial registration. If the system only took one sample, it wouldn't know how much your hand naturally shakes or how fast you usually move.

The goal of gesture_capture.py is to:

  1. Record 5 separate samples of your gesture.
  2. Ensure every sample is mathematically normalized.
  3. Compare all 5 samples against each other to calculate your personal consistency.
  4. Set 4 custom security thresholds that are tight enough to block attackers but loose enough to let you in reliably.

1 Program Startup & User Handling

When python gesture_capture.py executes, it starts in the main() function:

a) Banner & Username Prompt

==========================================================
   GESTURE AUTH — New User Registration
==========================================================

Enter a username to register: saimani

b) Handling Existing Users

If a folder named templates/saimani already exists, the system warns the user to prevent accidental data loss:

User 'saimani' already exists.
Do you want to overwrite the existing gesture? (y/n): y

If accepted, the old data is cleared right before new data is saved.

2 Webcam & Hand Tracking Setup

The system initializes MediaPipe Hands. For registration, the confidence thresholds are kept relatively high to ensure the baseline data is extremely accurate:

hands = mp_hands.Hands(
    static_image_mode=False,
    max_num_hands=1,
    min_detection_confidence=0.7, # 70% confidence needed to detect
    min_tracking_confidence=0.5,
)

OpenCV then opens the webcam and creates the graphical user interface.

3 The Multi-Sample Recording Loop

To measure human variation, the system requires NUM_REGISTRATION_SAMPLES = 5. It enters a loop that prompts the user 5 times.

The Recording Trigger

The system tracks the hand in real-time but does not record until the user presses [R].

The 3-Second Window

Once [R] is pressed, record_one_sample() starts a strict 3-second timer:

RECORDING_DURATION_SEC = 3
recording_start_time = time.time()
recorded_frames = []

For exactly 3.0 seconds (at ~30 FPS):

  • If a hand is detected, the 21 3D landmarks are converted to a NumPy array (21, 3) and appended to the list.
  • If the hand is lost, the frame is skipped.

4 Immediate Quality Control & Normalization

Before moving to the next sample, the captured 3 seconds of data must pass strict quality checks.

Rule 1: Minimum Frame Count

If the user's hand dropped out of frame too often, they might only have 8 recorded frames.

if len(recorded_frames) < 10:
    return None  # Gesture rejected. User must re-record this sample.

Rule 2: On-the-Fly Normalization

If the frame count is valid (e.g., 74 frames), it immediately goes through normalize_gesture():

  1. Spatial Normalization: Every frame is mathematically shifted so the wrist is at (0,0,0), and scaled down so the furthest fingertip is exactly 1.0 unit away.
  2. Temporal Normalization: The 74 frames are mathematically "stretched" or "squashed" using linear interpolation to become exactly 60 frames.

If successful, this normalized (60, 21, 3) sample is stored in memory, and the system prompts the user to record the next sample.

5 The Threshold Calibration Engine

🧠 The Core Math
This is the most crucial part of registration. This step calculates exactly how strictly the system will judge this specific user when they try to log in tomorrow.

Once all 5 samples are stored, the system calls compute_threshold_details().

The "Pairwise" Comparison Concept

To measure variation, the system compares the 5 samples against each other. Using combinatorial math (5 choose 2), this yields 10 unique pairs: (1vs2), (1vs3), (1vs4), (1vs5), (2vs3), (2vs4), (2vs5), (3vs4), (3vs5), (4vs5).

The system runs all 4 security gates on these 10 pairs to find the user's maximum natural mistakes.

Gate 1: DTW Distance Calibration

Let's say the 10 DTW distances are: [1.1, 1.2, 1.3, 1.0, 1.4, 1.2, 1.1, 1.3, 1.5, 1.2].

  • Mean: 1.23
  • Standard Deviation (Std): 0.14
  • Statistical Threshold: Mean + (2 * Std) = 1.51 (Covers 95% of normal variations).
  • Max Margin Threshold: Max distance * 1.25 = 1.5 * 1.25 = 1.875.

The system intelligently selects a safe ceiling, applying a strict floor of 2.0 to prevent the threshold from becoming impossibly tight.

Gate 2: Finger State Mismatch Calibration

Let's say the maximum finger mismatch among the 10 pairs is 0.08.

  • Margin Added: + 0.08 margin.
  • Calculated Limit: 0.08 + 0.08 = 0.16.
  • Hard Caps: Constrained between 0.12 and 0.30. Selected: 0.16.

Gate 3: Transition Order Calibration

Let's say the maximum sequence dissimilarity (edit distance) is 0.15.

  • Margin Added: + 0.08 margin.
  • Calculated Limit: 0.15 + 0.08 = 0.23.
  • Hard Caps: Constrained between 0.10 and 0.40. Selected: 0.23.

Gate 4: Segment Max Mismatch Calibration

Let's say the maximum segment mismatch in the 10 pairs is 0.12.

  • Margin Added: + 0.10 margin.
  • Calculated Limit: 0.12 + 0.10 = 0.22.
  • Hard Caps: Constrained between 0.12 and 0.50. Selected: 0.22.

★ Concrete Walkthrough: "Alice" Registers

Scenario
Alice decides to use a simple "Hand Wave" as her biometric password.
  1. Sample 1: Alice presses [R], waves. Captured 75 frames. Resampled to 60.
  2. Sample 2: Alice waves slightly faster. Captured 82 frames. Resampled to 60.
  3. Sample 3: 70 frames captured. Resampled to 60.
  4. Sample 4: 78 frames captured. Resampled to 60.
  5. Sample 5: 72 frames captured. Resampled to 60.

The Calibration Engine Result

Because temporal normalization squashed/stretched all waves to exactly 60 frames, the fact that Sample 2 was "faster" does not mathematically matter.

When comparing Sample 1 to Sample 2, the DTW distance is a tiny 1.1. The transition sequence for Sample 1 is exactly identical to Sample 2, making the dissimilarity 0.0.

After analyzing all 10 pairs, the engine realizes Alice is highly consistent. Her thresholds are set extremely tight (hitting the minimum floors for DTW at 2.0 and Transition at 0.10).

Because her thresholds are so tight, an attacker trying to mimic her wave with slightly incorrect finger timing will be immediately rejected. The capture pipeline has successfully personalized the AI's sensitivity perfectly for Alice!
